# 日夜切换性能修复

## 右侧滚动条

新增标题栏后，原来的画布高度与内容高度叠加，产生页面滚动条。当前根页面固定为窗口高度，禁用根页面滚动；内容使用增强 scroll-view，并设置 show-scrollbar 为 false。画布高度扣除标题栏占用空间，小屏幕内容仍可在容器中上下滚动，顶部标题和系统胶囊保持位置。

## 顶部标题栏

页面设置 navigationStyle 为 custom，新增固定的“天津之眼”标题栏。标题栏背景使用同一个 --page-bg，标题文字使用 --page-text，随画布回传进度变化。根据窗口状态栏高度和原生胶囊边界预留位置，不绘制替代胶囊，不调用修改系统前景色的 API。状态栏仍保留浅色底色，维持系统文字可读性。

最新编译配置已包含 custom；页面编译产物包含标题栏和布局测量逻辑。状态传递回归检查和胶囊高度预留检查通过。

## 页面与摩天轮区域同步变色

当前版本移除独立的页面 CSS 过渡计时。渲染引擎在成功绘制动画帧后通过 themechange 回传唯一的过渡进度，页面用同一进度计算背景、文字、面板和按钮颜色。WebGL 画布采用透明清屏，天空背景直接使用页面底色，保证画布边界两侧显示同一颜色。

读取 HBuilderV 最新编译页面进行链路测试，逐次采样验证页面颜色等于画布回传进度对应的颜色，并检查连续反向切换、暂停和隐藏/恢复。测试通过；实际微信页面的最终显示仍需重新编译后确认。

## 当前动画调整

日夜过渡改为约 1 秒的阻尼曲线，天空、水面、灯光、云朵透明度和星星透明度共用一个进度。连续反向切换保留当前进度和变化速度，不重新从静止开始。页面颜色使用 900ms CSS 过渡，使界面与场景的变化节奏接近。

云朵和星星始终保留在渲染图中，用透明度渐变代替 visible 瞬间显隐。星星在第一个正常动画帧中准备资源，不使用同步初始化预热。过渡期间尝试以 60fps 为目标，结束后恢复约 30fps；实际帧率受设备性能影响。颜色过渡采用实际帧间时间，避免掉帧时被运动的时间步长上限拖慢。

验证：首次夜景切换无新增几何上传和 shader link；采样确认装饰透明度互补、进度在 0～1 之间、快速反转时进度与速度连续、最终状态稳定；页面到原生画布的状态链路、暂停和隐藏/返回检查通过。检查仍为浏览器适配测试，最终观感需在微信环境复测。

## 页面变暗但画布仍为白天

用户截图显示页面主题已经切换，但画布背景、云朵和模型灯光没有切换。此前仅验证了渲染引擎，未覆盖 uni-app x 页面对原生组件的状态传递，因此不能用此前的引擎测试认定微信端切换正常。

本次给原生组件增加稳定 ID 和 applyState 方法；页面在状态变化、组件就绪、页面显示时，通过 selectComponent 发送完整状态。原属性 observers 保留，两条路径复用同一状态处理，防止缩放、复位和重载重复执行。

已读取 HBuilderV 自动生成的最新页面 JS/WXML，确认包含 syncScene、applyState 调用与组件 ID。使用这些实际编译产物，在关闭通常的 u-p 属性转发的测试环境中，验证“夜间按钮 → 页面 watcher → 原生组件 → 真实 WebGL 画布”整条链路：背景变暗、星星出现、云朵隐藏；反复切换、暂停、隐藏/恢复和返回白天通过。测试运行在浏览器适配环境，尚不等同微信模拟器/真机验收。

本次修改 `wxcomponents/tianjin-scene/lib/scene.js`，保留现有 AppID 配置。

- 已撤回同步启动预热（compile 和连续 render）：原生画布在动画帧回调中开始绘制，避免初始化阶段的同步渲染阻塞。首次显示星星仍会有一次几何数据上传。
- 动态阴影按 15 Hz 更新，主画面仍以约 30 fps 为目标；暂停后缓存阴影。灯光亮度和水面颜色变化无需重绘阴影。
- 颜色与灯光过渡改为 0.45 秒的有限过渡，结束后停止插值；快速反向切换从当前颜色继续。
- 装饰星星不再投射或接收阴影。
- 相同尺寸的 resize 调用不再重新设置画布大小或重置镜头。

## 验证

通过真实 WebGL1 上下文与原生画布适配器做修改前后对比，执行首次切换、8 次往返、快速连续切换、暂停、页面隐藏/恢复和销毁。

- 初版预热实验的首次夜景 bufferData 调用为 3 → 0，但该预热方案已因微信白屏反馈撤回，不作为当前版本的验证结论。
- 切换期间新增 shader link 调用：0。
- 8 次往返各渲染 20 帧，总绘制调用：65,360 → 49,322（减少约 24.5%）。这些调用包含阴影绘制。
- 过渡结束后颜色保持稳定；暂停时摩天轮角度不变；连续切换最终模式正确。
- 原有手势、缩放、复位、尺寸变化和资源释放回归检查通过，无脚本或渲染错误。

上述结果来自桌面 Chrome 软件 WebGL 的受控检查，不代表微信开发者工具或手机的实测帧率。仍需在你的微信环境中确认卡顿是否消除。

- 调整后日夜、手势、暂停/恢复、缩放、尺寸变化与释放检查通过，无脚本/渲染异常；微信白屏的根因仍需结合开发者工具错误日志确认。
